## Why `.claude/agents` + `.claude/skills` get zero writes

Their `name:`/`description:` frontmatter is machine-read by Claude Code to register skills and agents. Any bug in a frontmatter-merge script that touches these 244 files risks breaking skill/agent loading — the downside is disproportionate to the upside (a graph edge). Instead: build `AGENTS_MOC.md` and `SKILLS_MOC.md`, generated by reading (not writing) each file's existing frontmatter, listing name + description + a real `[[wikilink]]` to the file. The MOC creates the edge; the source file is untouched.

## Mechanism for the ~1,130 firm-content files

Additive-only frontmatter merge (never touches body prose, never overwrites existing keys — only adds missing ones):

```yaml
type: <taxonomy value, see below>
tags: [<type>, <top-level-folder-slug>]
status: active | paused | killed | archived   # only when inferable, else omitted
owner: <agent-slug>                             # only when inferable from content/folder convention, else omitted
killed_by: "[[K-xxx]]"                          # only for killed strategies/ideas with a known lesson
moc: "[[<path to this file's MOC>]]"            # real link field — this is the graph edge
```

Files that already carry complete frontmatter (the 39 decision notes, any already-generated note) are left alone — the script only backfills missing fields, never restructures existing ones.

## Script

`Shreyas_Ionic_AMC/05_DATA_OFFICE/scripts/build_vault_connectivity.py`

- Exclusion list is an explicit config block at the top (paths, not scattered logic) — auditable, extendable.
- **Dry-run mode first**: prints a diff summary (files to be touched, frontmatter fields to be added, MOCs to be created/regenerated) without writing anything. Human reviews before the real run.
- Idempotent / rerunnable — safe to run again after new files are added to the vault.
- Preflight checks the open dependencies Librarian flagged: confirms what `imported_research/` and `BROAD_RESEARCH_2036/` actually contain, and whether `CURATION_REPORT.md` already has lesson↔kill linkage — prints these as part of the dry-run summary rather than assuming.
