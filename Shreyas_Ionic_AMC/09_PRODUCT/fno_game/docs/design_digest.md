## preindex
tools/build_index.py — one-time (re-runnable, idempotent) script, pure pandas/pyarrow. Pass 1 (spot): group NIFTY.parquet by trading_day (after tz-convert to IST and >=09:15 filter — both landmines enforced here, once); a day is spot-eligible if it has >=360 bars covering 09:15–15:29 and has a prior trading day (for D-1 chart) and >=5 prior sessions in-file (for prev-week H/L). Pass 2 (options): map each spot-eligible day to the nearest expiry file with expiry >= day among the 262 files (verified on disk); open that parquet's trading_day column only (pyarrow column projection, cheap), and require: >=8 strikes within ±200 of the day's spot open having >=60% minute coverage in 09:15–15:25, for both CE and PE. Days failing option coverage are logged to coverage_gaps.json with the reason (missing expiry file / thin strikes / partial-day data) — this doubles as the expiry-gap flag report. Pass 3 (lot size): iterate fo_YYYYMMDD.csv bhavcopies, take NIFTY FUTIDX rows, lot = round(VAL_INLAKH*1e5 / (CONTRACTS * SETTLE_PR)) snapped to the known NIFTY ladder {75,50,25}; emit lot_sizes.json as effective-date ranges and cross-check against the known history (75->50 in 2021, 50->25 Apr-2024, 25->75 Nov-2024); any date whose derived lot doesn't snap cleanly is flagged for manual review rather than guessed. Output: fno_game/data/eligible_days.json [{date, expiry_file, dte, spot_bars, strike_coverage, lot_size}], coverage_gaps.json, lot_sizes.json. Expected runtime: minutes (262 files x column-projected reads).

## persistence
SQLite (fno_game/data/fno_game.db, WAL mode) — chosen over JSONL because the analytics dashboard is exactly the workload SQL is for (GROUP BY setup/DTE/hour, window functions for expectancy), it's stdlib (sqlite3), single-file, and ACID across the bankroll+trades+registry commit at session end. JSONL kept ONLY as an append-only raw order-event audit log (events.jsonl) for debugging, never read by analytics. OneDrive caveat: WAL + a .odignore/'Always keep on this device' note in README, since OneDrive sync can lock DB files mid-write. Schema: bankroll(id=1, cash REAL, updated_at); bankroll_resets(reset_at, old_cash, new_cash); played_days(real_date TEXT PK, session_id, played_at) [no-repeat registry]; sessions(session_id PK, real_date, expiry_date, dte, lot_size, start_capital, end_capital, gross_pnl, total_costs, net_pnl, n_trades, started_at, ended_at, status[completed/abandoned], squareoff_time); orders(order_id PK, session_id FK, sim_minute, action[BUY/SELL], strike, cp, lots, order_type[MKT/LMT], limit_price, status[FILLED/OPEN/CANCELLED/REJECTED_MARGIN/EXPIRED], fill_price, fill_sim_minute, slippage_rs, brokerage, stt, exch_txn, gst, sebi_stamp, total_cost_rs); trades(trade_id PK, session_id FK, strike, cp, direction[LONG/SHORT], lots, entry_order_id, exit_order_id, entry_minute, exit_minute, entry_price, exit_price, entry_spot, dte, gross_pnl, net_pnl, exit_reason[MANUAL/SQUAREOFF/EXPIRY_SETTLE], mae_rs, mfe_rs, hold_minutes) [MAE/MFE rolled up at close so the dashboard never scans marks]; position_marks(session_id, trade_id, sim_minute, ltp, unrealized_pnl, PRIMARY KEY(trade_id,sim_minute)) [written by the tick loop each minute a position is open — the MAE/MFE raw material and the review-screen excursion chart]; journal(entry_id PK, trade_id FK NULL, session_id FK, tag_type[SETUP/MISTAKE/EMOTION], tag TEXT, note TEXT, created_at); equity_snapshots(session_id, sim_minute, equity) for the intraday equity curve. Every analytics query (win rate, R:R = avg_win/avg_loss, expectancy, P&L by hour-of-day/DTE/setup-tag, MAE/MFE scatters) runs off these tables alone — no parquet re-parse ever.

- Data gaps inside the 2021-2026 window (thin early-2021 coverage, any missing expiry files among the 262) will shrink the eligible-day pool — quantified honestly by coverage_gaps.json in P0 before the Principal expects 'any random day'
- Costs realism drift: STT/exchange-txn rates changed over 2021-2026 (STT on options raised Oct-2024); v1 applies today's flat rates to all historical days per the locked 'flat realistic' requirement — note it in README so net-P&L isn't misread as historically exact

# EDGE CASES

### Lot size history (VERIFIED ON DISK — memory is wrong)
ISSUE: The 2021-2026 window contains FIVE lot eras, not four. Verified from bhavcopy on disk: front contracts were 75 at window start (Jun-2021 expiries), 50 from Aug-2021 expiries, 25 by May-2024 (verified fo_20240502: ALL expiries incl. Dec-2024 quarterly = 25, i.e. the Apr-2024 downward revision changed lots MID-LIFE on far contracts), 75 for new contracts from ~Nov-20-2024 (verified fo_20241203: Jan-02-2025 weekly = 75 while Dec-2024 weeklies = 25), and 65 from Jan-2026 (verified fo_20260101 onward: all NIFTY = 65 — a transition after most memory cutoffs). Any hardcoded table WILL be wrong.
DECISION: Build a lot_table.parquet keyed on (trading_day, expiry_date) at game-build time from the 402 fo_*.csv files on disk; the game engine reads lot ONLY from this table, never from a constant. For a game day D and traded expiry E with no bhavcopy row on D, use the observation of E from the nearest bhavcopy date, and hard-assert that all observations of E within ±10 trading days of D agree; contradictions = exclude day D from the eligible pool and log. Also hard-assert every derived lot is in {25, 50, 65, 75}.

### Lot size derivation — dual bhavcopy schema
ISSUE: fo_*.csv has TWO schemas: old NSE format (INSTRUMENT/SYMBOL/CONTRACTS/VAL_INLAKH/SETTLE_PR, expiry '24-Jun-2021') until mid-2024, and UDiFF (TckrSymb/FinInstrmTp='IDO'/'IDF'/XpryDt ISO/NewBrdLotQty) after. Verified: old-schema options VAL_INLAKH is NOTIONAL (strike+premium): median over strikes of VAL_INLAKH*1e5/(CONTRACTS*(STRIKE_PR+CLOSE)) snaps exactly to 75.0/50.0/25.0; premium-based hypothesis gives garbage (~727607).
DECISION: Lot builder: if header contains 'NewBrdLotQty' read it directly per (TradDt, XpryDt) for TckrSymb=NIFTY. Else compute per EXPIRY_DT the median of VAL_INLAKH*1e5/(CONTRACTS*(STRIKE_PR+CLOSE)) over OPTIDX NIFTY rows with CONTRACTS>50 and CLOSE>0, snap to nearest of {25,50,65,75} with 12% tolerance, reject the day if no snap. Cross-check with FUTIDX rows: VAL_INLAKH*1e5/(CONTRACTS*SETTLE_PR).

### Lot size — same-day mixed lots
ISSUE: On a single trading day different expiries carry different lots (verified 2024-12-03: Dec weeklies 25, Jan-02 weekly 75, Jan-30 monthly 25; verified 2021-07-05: Jul weeklies still 75 while Jul-29 monthly already 50). A per-day lot is structurally wrong in transition months (Jul-2021, Apr-May-2024, Nov-2024-Jan-2025, Dec-2025-Jan-2026).
DECISION: Lot lookup is ALWAYS (trading_day, expiry_date) — sizing, margin, P&L, and costs all take lot from the specific traded expiry's row. If the player trades both front and next weekly during a transition week, the two positions may legitimately have different lot sizes; UI shows lot per contract row in the chain header.

### Weekly expiry weekday migration (VERIFIED ON DISK)
ISSUE: Expiry files on disk: Thursday standard through 2025-08-28 (last Thu), Tuesday from 2025-09-02 (SEBI single-expiry-day rule; NSE chose Tuesday). Plus holiday-shifted expiries: Wed 2021-08-18, 2022-04-13, 2023-01-25, 2023-03-29, 2023-06-28, 2024-04-10, 2024-08-14, 2025-04-09, 2025-04-30, and Mon 2026-03-02, 2026-03-30, 2026-04-13 (Tuesday-holiday prepones to Monday). Any weekday-rule-based expiry computation breaks on all of these.
DECISION: NEVER compute expiry from weekday rules. The expiry parquet filename list IS the calendar: for sim day D, front weekly = min(expiry_date >= D among files whose parquet contains rows with trading_day == D); next weekly = the following such expiry. DTE = (expiry_date - D).days in calendar days. Display DTE only — the expiry's weekday and date are never rendered (a 'Tue expiry' label instantly reveals post-Sep-2025).

### Expiry-day settlement mechanics
ISSUE: NIFTY weeklies are European, cash-settled at the final settlement price = closing index value (last-30-min average), NOT the 15:29 last trade. A position held to 15:30 on expiry settles at a price the player never saw tick. Longs exercised ITM pay STT 0.125% on intrinsic (settlement) value (post-Aug-2019 regime; the pre-2019 full-notional STT trap no longer applies); selling before close pays 0.1% on premium instead — plus you keep control of price.
DECISION: Settlement spot = mean of NIFTY 1-min closes for bars stamped 15:00-15:29 (30 bars). Auto square-off engine runs at 15:25 on every day. On expiry day, if a leg cannot fill by 15:29 (zero volume), cash-settle it: OTM legs expire at 0 (shorts keep premium, no exit costs); ITM long legs credit lot*max(0, intrinsic vs settlement spot) minus STT 0.125%*intrinsic*lot; ITM short legs debit lot*intrinsic with no STT. Show a banner at 15:15 on expiry day: 'ITM positions held to close settle at the 30-min average and longs pay 0.125% exercise STT — selling is usually cheaper.'

### Which expiries are tradable
ISSUE: On expiry day the front weekly is 0 DTE; traders also roll to the next weekly. Restricting to one expiry breaks realism; on monthly-expiry weeks the 'front weekly' file IS the monthly contract.
DECISION: Every sim day offers exactly the two nearest weekly expiry files (labeled '0-6 DTE' and 'next, N DTE'). Monthly-expiry-week contracts are treated identically (they are just an expiry date in the file list). Strikes offered: those present in the file for trading_day==D within ±200 points of the CURRENT spot mark; the window re-centers as spot moves; positions whose strike drifts outside the window can still be exited, but new entries there are blocked.

### Cost table (today's rates, uniform across eras)
ISSUE: Rates changed mid-window (STT sell-premium 0.0625%→0.1% on 2024-10-01; NSE txn charge slab→flat 0.03503% same date). Per-era costs would make identical trading skill score differently by hidden date — noise for a training tool, and per-era tables leak the date in the fill confirmations.
DECISION: Apply TODAY's rates uniformly to all replayed eras (state this in the review screen). Per executed order, on premium turnover V = fill_price*lot*n_lots: brokerage ₹20 flat; STT 0.1%*V on SELL orders only (every sell — open or close); NSE txn charge 0.03503%*V both sides; IPFT 0.0005%*V both sides; SEBI fee 0.0001%*V both sides; stamp duty 0.003%*V on BUY orders only; GST 18% on (brokerage + txn + IPFT + SEBI). Exercise settlement: STT 0.125% of intrinsic value on long ITM only, no brokerage on expiry settlement. Round each component to ₹0.01. Net P&L (after all costs) is the only P&L ever displayed.

### Margin — naked short index option
ISSUE: Real SPAN is a 16-scenario scan, not implementable from 1-min bars; need a calibrated closed form that yields ~₹0.9-1.2L for an ATM short weekly at spot ~25,000, lot 75.
DECISION: M_naked = lot * [ P + max(0.045*S - OTM, 0.025*S) ], where P = current option mark, S = current spot mark, OTM = max(0, K-S) for CE and max(0, S-K) for PE. Calibration check: S=25,000, P=160, ATM → 75*(160+1125) = ₹96,375 ✓; deep OTM floor 75*(10+625) = ₹47,625. Recompute on every completed 1-min bar for all short legs; long options carry zero margin (premium debited from cash at fill).

### Margin — defined-risk verticals
ISSUE: Post-2020 NSE portfolio margining gives large spread benefit; charging naked margin on hedged books ruins the strategy space the game is meant to teach.
DECISION: For a paired short+long of same type, same expiry, long qty >= short qty: credit spread (long strike further OTM) margin = lot * max(width - net_credit, 0.005*S); debit spread (long strike more ITM than short) margin = 0 (max loss = net debit already paid). Width = |K_long - K_short|. Pairing recomputed after every order via the portfolio pairing rule below.

### Margin — straddle/strangle and portfolio pairing
ISSUE: Short CE + short PE cannot both lose fully; exchanges charge roughly the bigger leg plus the smaller leg's premium. Also the book must be decomposed deterministically so margin is reproducible.
DECISION: Greedy pairing per expiry, run after every fill and every bar: (1) pair each short with the cheapest available same-type long that covers it → vertical margins; (2) among remaining naked shorts, pair the largest CE with the largest PE → M_pair = max(M_naked_CE, M_naked_PE) + lot*P_mark_other, repeat while both sides have naked shorts; (3) leftover naked shorts additive at M_naked. Total margin = sum. Order rejected pre-trade if resulting total margin + premium debits > (cash + option credits received).

### Margin — expiry-day and era note
ISSUE: Brokers add expiry-day ELM on shorts; also pre-Sep-2021 the real world allowed intraday margin discounts (peak-margin phase-in), which per-era emulation would leak dates.
DECISION: Uniform rules across eras (consistent with uniform costs): full margin always (no intraday discount emulation), plus a flat 1.3x multiplier on all SHORT-leg margin components on expiry day from 09:15. Do NOT block far-OTM long buying on expiry day (that broker behavior targets stock-option delivery risk; index is cash-settled) — instead show a one-line broker-realism note in the review.

### Margin call / RMS behavior
ISSUE: Intraday MTM losses on shorts can push utilization over 100% mid-session; real brokers RMS-square you off, and a game that just lets margin go negative teaches fake risk tolerance.
DECISION: On each completed bar: utilization = margin_required/(cash + credits - MTM_loss). >100% → persistent orange warning + block all new margin-increasing orders. >110% for 5 consecutive bars → auto RMS square-off of the single highest-margin position at market via the normal fill engine, tagged 'RMS-forced' in the trade log (counts in analytics as a mistake-class event).

### Fill — market orders
ISSUE: With 1-min OHLC you never know the intrabar book; filling at the current bar's close is lookahead, filling at LTP is stale.
DECISION: Market order placed at sim-minute t fills at the NEXT 1-min bar of that strike: price = next bar open + 1 tick (₹0.05) adverse for buys, − 1 tick for sells. If the strike has no bar (or zero-volume bar) at t+1: look forward up to 3 minutes for the first bar with volume>0 and fill at its open ± (1 tick + 1 extra tick per minute waited). ENTRY orders with no qualifying bar within 3 min → REJECT with 'no liquidity' (mirrors the firm's D-031 limit-or-skip doctrine: never assume fills in dead markets). EXIT orders instead stay queued and fill at the first traded bar's open ± 2 ticks, so a player is never permanently trapped by the reject rule.

### Fill — limit orders
ISSUE: Touch-equals-fill on bar extremes is the classic backtest optimism: if bar low == your buy limit you were likely last in queue and unfilled.
DECISION: Standard conservative rule: a resting buy limit L fills only on a bar with volume>0 where low < L strictly (or open <= L, in which case fill at open, i.e. price improvement); sell limit fills only where high > L strictly (or open >= L → fill at open). Touch without penetration = no fill. Limit orders persist until filled, cancelled, or 15:25 square-off.

### Fill — SL-M (stop-loss market)
ISSUE: Intrabar path is unknown; triggering on close misses gaps, triggering optimistically at the trigger price understates slippage on fast bars.
DECISION: SL-M buy (covering shorts) triggers on the first bar where high >= trigger; SL-M sell triggers where low <= trigger. Once triggered it becomes a market order: fill at max(trigger, next bar open) + 1 tick for buy stops, min(trigger, next bar open) - 1 tick for sell stops — i.e. gaps through the trigger fill at the (worse) next open, never at the trigger.

### Fill/quote — illiquid strikes with no bars
ISSUE: Far strikes routinely print no bars for many minutes; showing a firm-looking price there invites orders that could never fill.
DECISION: Chain rows whose last traded bar is >10 min old render greyed with a staleness badge ('last trade 14m ago') and BLOCK new entry orders (button disabled); >30 min old renders '—' for price/IV. Exits on such strikes go through the queued-exit path. Strikes with zero rows for the whole day are hidden from the chain entirely.

### Intrabar lookahead in the sim clock
ISSUE: If the UI renders the currently-forming 1-min bar (its final OHLC comes from the file), the player sees one minute into the future — subtly but fatally unrealistic.
DECISION: The sim clock advances in whole minutes; at sim time t the chart and chain show ONLY bars with timestamp <= t-1 (fully completed). The forming bar is never rendered. This composes with the fill rule (orders at t fill at bar t+1 open) to make lookahead structurally impossible.

### Data — missing minutes / gaps
ISSUE: Both spot and option series have missing minutes; naive iteration by row index desynchronizes the clock from wall time and misaligns spot vs option marks.
DECISION: The master clock is wall-clock minutes 09:15→15:30, not row count. A missing spot minute renders as a gap (no candle), marks carry the last completed bar forward, and the replay speed is unaffected. Never interpolate prices. Days failing the coverage screen (below) can't be sampled anyway.

### Data — eligible-day screen (truncated days, half days, Muhurat)
ISSUE: Truncated days, Muhurat evening sessions (~1hr, outside 09:15-15:30), exchange-outage days, and the dataset's first week would produce broken sessions (no prev-day chart, dead chains, phantom square-offs).
DECISION: Precompute an eligibility index once: day D is in the sampling pool iff (1) spot has >=360 bars in [09:15,15:29] and a bar at >=15:25; (2) first regular bar is 09:15 IST (auto-excludes Muhurat/special sessions); (3) the front-weekly file has, for trading_day==D, >=5 strikes with volume>0 within ±200 of D's 09:15 spot; (4) D-1 trading day exists with >=360 bars (prev-day chart); (5) >=5 prior trading days exist (prev-week levels); (6) lot table has a consistent entry for (D, front expiry); (7) D not already played (persisted in the SQLite career DB).

### Data — freak prints / circuit bars in options
ISSUE: 1-min option series contain single-bar 5-10x spikes (fat-finger prints, crossed quotes at open); filling or marking against them creates windfall P&L that never existed.
DECISION: Fills: if the candidate fill bar's open deviates >30% from the same strike's previous traded close, skip that bar and fill at the following qualifying bar (freak-bar skip, logged). Marks: MTM mark uses a median-of-3 filter over the last three traded closes ONLY when the newest close deviates >3x from both neighbors; raw closes otherwise. Chart candles are drawn raw (traders should see the spike) with the skip noted in the fill log.

### Data — pre-open auction bars (known landmine)
ISSUE: Bars before 09:15 are pre-open auction prints; including them corrupts the day open, gap calcs, first candles, and any 09:00-anchored aggregation (project-verified: ~94% of days affected in this dataset).
DECISION: Hard filter timestamp >= 09:15 IST at the data-loader boundary for spot, options, AND VIX — one shared loader function so no code path can bypass it. Day open = 09:15 bar open. Add a unit test asserting no loaded frame ever contains a <09:15 bar.

### Data — timeframe aggregation alignment
ISSUE: Resampling 1-min to 3m/5m/15m/30m/1h with default 00-minute anchoring produces bars starting 09:00/09:30 that mix nonexistent minutes; Indian convention anchors to 09:15.
DECISION: All aggregation buckets anchor at 09:15 (3m: 09:15,09:18,...; 15m: 09:15,09:30,...; 1h: 09:15,10:15,...,15:15 with a partial final bucket to 15:29). The forming bucket at sim time t aggregates only completed 1-min bars <= t-1 and is drawn as an in-progress candle. Same anchoring for the prev-day chart.

### Data — prev-day / prev-week levels
ISSUE: 'Previous day' must be the previous TRADING day from the data (Friday for Monday, pre-holiday day otherwise) and prev-day high/low must exclude pre-open prints; prev-week H/L must span the prior 5 trading days, not a calendar week.
DECISION: Prev-day = the nearest earlier date present in the spot parquet; H/L computed from its >=09:15 bars only. Prev-week H/L = max/min over the 5 trading days ending at prev-day. Lines labeled 'PDH/PDL/PWH/PWL' with values but never with dates. The prev-day chart panel is labeled 'D−1', not a date or weekday.

### Blind-date leak — chart axes and journal
ISSUE: Date on the x-axis, tooltip timestamps, filenames in exports, or the trade-log timestamps shown mid-session all reveal the day instantly.
DECISION: All UI timestamps render time-of-day only (HH:MM). Internally every record stores the real timestamp; the session UI masks the date component until the reveal screen, after which the session's journal entries display full dates. Exports/screenshots generated mid-session use the session UUID, not the date.

### Blind-date leak — weekday and expiry code
ISSUE: Showing 'Monday' or an expiry weekday narrows the era hard (Tue expiry = post-Sep-2025; Mon-shifted expiry = 2026). Standard contract codes (NIFTY25903...) contain the full date.
DECISION: Never display the sim day's weekday nor the expiry's weekday/date. Contract label format: 'NIFTY <strike> <CE/PE> · <N> DTE' plus moneyness tag ('ATM+100'). DTE in calendar days; on 0 DTE additionally show hours-to-expiry. The reveal screen shows the real contract codes.

### Blind-date leak — lot size (the subtle one)
ISSUE: The player MUST know the lot to size orders, but 25 vs 50 vs 65 vs 75 maps to era buckets (65 = 2026 exactly). Hiding it breaks sizing; normalizing to a synthetic lot distorts margin and premium realism.
DECISION: ACCEPT the leak, display the true lot. Rationale (documented in-game): real strike/price levels are already shown per the locked requirements, and NIFTY's spot level dates the session far more precisely (15,600 ≈ mid-2021, 24,000 ≈ late-2024) than the lot bucket adds. Blinding is best-effort against recall, not information-theoretic. All quantities entered in LOTS; the units multiplier shows in the order ticket.

### Blind-date leak — VIX and famous days
ISSUE: VIX level hints at era (2021 elevated vs 2023 sub-11); landmark sessions (2024-06-04 election crash, budget days) are recognizable from the tape itself within minutes.
DECISION: Show VIX (essential trading input; accepted residual leak). Keep landmark days IN the pool — they are the highest-value practice days — but tag them in the post-session review ('this was election results day'). Maintain an optional config blacklist (default empty) for players who want them excluded. No-repeat sampling already prevents memorizing a replayed day.

### Sampling — no-repeat career pool
ISSUE: Re-serving a played day lets the player 'predict' the tape; naive random-with-replacement will repeat within ~35 sessions (birthday problem over ~1,200 days).
DECISION: Persist played trading_days in the career SQLite DB; sample uniformly WITHOUT replacement from (eligible − played). Explicit reset of the bankroll to ₹10L asks separately whether to also reset the played-days list (default: keep, so tape memory can't be farmed). When the pool empties, tell the player and require an explicit pool reset.

### Greeks/IV — time-to-expiry and rates
ISSUE: Day-count T on a 0-2 DTE weekly is off by up to 100%; naive T=0 at expiry afternoon divides by zero; risk-free rate and dividend fussing add noise without value at this tenor.
DECISION: T = max(minutes_to_expiry, 1)/525600 years, where expiry moment = 15:30 IST on the expiry date and 'now' = sim time. r = 6.5% flat across all eras (≈91-day T-bill; at <7 DTE the r-sensitivity is negligible). q = 0 (skip dividend adjustment; NIFTY weekly premia carry immaterial dividend value). Forward = S*e^(rT) with spot = last completed spot bar close. Note in code comments: synthetic forward from ATM put-call parity is the v2 upgrade if smile skews look shifted.

### Greeks/IV — solver robustness
ISSUE: Deep-ITM options with stale prints often have mark < intrinsic (no IV solution); 0-volume strikes give IV explosions; near-expiry OTM IVs legitimately hit 100-300% and naive caps distort the display.
DECISION: Solve IV by bisection on [0.01, 5.00] against Black-Scholes; tolerance 1e-6 on price. If mark < intrinsic - 0.05 → IV = '—', delta = ±1.00, gamma/vega = 0, theta = 0 (settlement drift only). Strikes with last trade >5 min old show IV greyed with the staleness badge and are EXCLUDED from the smile chart and from any ATM-IV headline number. Cap displayed IV at 400% with a '>' indicator; never cap the internal solve.

### Marks and MTM P&L
ISSUE: With 1-min OHLC there is no bid/ask mid; the only defensible mark is last traded close, but on illiquid strikes that mark can be many minutes stale and silently misstate P&L and margin.
DECISION: Mark(strike, t) = close of that strike's most recent bar with timestamp <= t-1 (completed bars only), passed through the freak-print median filter. Staleness badge on any position mark >5 min old; positions with all-stale marks show P&L as 'stale ~₹X'. Margin, MTM curve, and RMS logic all use this same mark function — one implementation, imported everywhere (no second definition allowed).

### Square-off engine (15:25 daily)
ISSUE: Force square-off must go through the same fill physics as the player, and a dead strike at 15:25 (the '61% dead back-leg' problem this firm has already measured) must not hang the session or fill at fantasy prices.
DECISION: At 15:25 all open positions are sent as market exits through the normal fill engine (queued-exit mode, ±2 ticks). New entry orders are blocked from 15:20. Non-expiry day: anything still unfilled at 15:29 is cash-settled at its last mark − 2 additional ticks penalty, tagged 'forced-settle' (analytics counts it as an exit-liquidity mistake). Expiry day: unfilled legs go to the settlement mechanics item instead (intrinsic vs 30-min-average settlement price, exercise STT applied).

### Order size — exchange freeze quantity
ISSUE: NSE rejects single option orders above the freeze quantity (currently 1,800 units for NIFTY); a game that lets a player whale 100 lots in one click at bar-open price teaches impossible execution.
DECISION: Cap any single order at 1,800 UNITS uniformly across eras (today's convention, consistent with uniform costs): max lots per order = floor(1800/lot) → 24 lots @75, 27 @65, 36 @50, 72 @25. Larger intents must be split into multiple orders, each paying its own ₹20 brokerage and each filling on subsequent bars (the natural cost of size).

### Bankroll persistence and blow-up
ISSUE: Career capital persists across sessions; a mid-session token/app crash must not vaporize a day's P&L, and negative equity (short gamma gap) must have defined semantics.
DECISION: SQLite career DB written transactionally: every fill, every completed session (final equity, day hash), every journal tag. Crash recovery: an unfinished session is voided (bankroll reverts to pre-session value; the day returns to the pool) — no mid-session resume in v1. If session-end equity <= ₹0: mark career 'blown up', freeze play, require explicit reset to ₹10L; the blow-up remains permanently in the analytics history.

### Tick size and price display
ISSUE: NIFTY option tick is ₹0.05; computed fills (open ± ticks) and cost-adjusted averages can produce off-tick prices that look fake and break P&L reconciliation against the tape.
DECISION: All fill prices rounded to the nearest ₹0.05 AFTER slippage adjustment (data prices are already on-tick). Costs live in a separate 'charges' column, never blended into fill price. P&L reconciliation identity asserted per trade in tests: net = (sell_value - buy_value) - total_charges, with settlement legs using settlement value.

### VIX display data
ISSUE: vix_1min.parquet may not cover every eligible day (spot data spans 2021-2026; VIX file coverage must be checked per day), and a missing-VIX panel pattern could itself hint at the era.
DECISION: At eligibility-screen build time, join VIX coverage per day. If 1-min VIX is missing for day D but daily VIX exists, show the day-open VIX as a static value labeled 'VIX (day)'. If neither exists, exclude D from the pool (cleaner than a leaky missing panel). VIX bars filtered to >=09:15 like everything else.

### Strike step and chain construction
ISSUE: Assuming a fixed 50-point strike grid breaks if the file contains 100-step far strikes or if a future era changes the step; the ±200-point window must be computed off live spot, not day-open.
DECISION: Chain shows exactly the strikes present in the expiry file for trading_day==D within ±200 of the CURRENT spot mark, sorted; step is whatever the data contains (assert min step == 50 for NIFTY in a build-time validation, warn if violated). ATM = strike minimizing |K - spot|; moneyness labels derived from that live ATM.

# RED TEAM

### [training/high/fix:v1] Fill model teaches that liquidity is free. Next-bar fill + 1-tick slippage means every order is honored near the printed price. Live NIFTY weeklies have a bid-ask spread (tight ATM, 0.5-2+ rupees on OTM wings and in fast markets) plus queue priority. The player will develop high-turnover, scalp-adjacent habits whose entire edge lives inside the spread the game does not charge — the single most reliable way sim profits evaporate live.
MITIGATION: Conservative fill engine in v1: market orders cross a modeled spread f(premium, moneyness, DTE, bar volume, bar range, time-of-day) with a stress multiplier on high-range bars; limit orders fill only on trade-THROUGH (price beyond limit by >=1 tick), not touch; zero-volume bars = no fill (D-031 limit-or-skip doctrine, already firm law). Reuse lib/execution_realism.py philosophy.

### [training/high/fix:v1] Zero real-money pain makes revenge trading free. Simulated courage does not transfer; the player learns to average down, martingale after losses, and hold through pain because the worst case is a number on a screen. This is the classic sim-to-live gap and no bankroll gimmick fully closes it.
MITIGATION: Make consequences as real as possible: persistent career bankroll (already locked), a daily loss limit that force-ends the session, an automatic 1-day 'suspension' after breaching it, and an append-only equity curve the player can never delete. Explicitly brief the Principal that game stats are an upper bound on live performance. Residual gap is inherent — acknowledge it in the analytics dashboard as a standing caveat.

### [training/med/fix:v1] 60x replay speed trains impatience. A 6.25-hour session compressed to ~6 minutes gives the player 60x the decision density of live trading and never trains the actual killer skill: sitting through hours of nothing without manufacturing a trade. Stats earned at 60x and at real-time are different games mixed into one ledger.
MITIGATION: v1: log playback-speed profile per session and per trade; segment all analytics by speed band; display trades-per-sim-hour vs a live baseline. v2: require a quota of sessions at <=5x before career stats 'certify'.

### [training/med/fix:v1] Era recall silently converts hindsight into fake skill. The accepted era-leak (real strikes ~ real spot level) means a player who pins 'this is June 2024 election week' trades memory, not process — and without measurement you cannot separate recall-wins from process-wins in the career stats.
MITIGATION: Mandatory end-of-session prompt BEFORE reveal: 'Did you recognize this day? Enter your date guess.' Auto-compare with truth; sessions with a correct/near guess get a RECOGNIZED flag and are segmented (default-excluded) in analytics. Cheap to build, must ship v1.

### [training/med/fix:v1] 2021-2026 contract mechanics are not today's market: NIFTY lot size changed (50 -> 25 -> 75), STT on option sells rose (0.0625% -> 0.1% Oct 2024), weekly expiry moved Thursday -> Tuesday (Sep 2025), and 0DTE microstructure evolved. Training on per-date historical mechanics builds instincts for a market that no longer exists.
MITIGATION: Design decision, needed before build: apply TODAY'S regime (current lot size, current cost table, current expiry-day convention for DTE labeling) uniformly to all replayed days — historical prices, current frictions. Reveal the historical-vs-applied differences in the post-session review. Derive historical lot sizes from bhavcopy only for sanity checks, not gameplay.

### [training/med/fix:v1] Rupee-anchored sizing on a fixed 10L bankroll will not transfer if real capital differs; the player learns '2 lots feels right' instead of '1% risk feels right'. Career bankroll growth compounds the distortion — late sessions are sized differently from early ones, and rupee P&L averages become dominated by the largest-bankroll era.
MITIGATION: All analytics in % of capital and R-multiples as primary units, rupees secondary. v2: allow reset-to-configurable-bankroll matching intended real capital.

### [training/med/fix:v1] Sampling bias temptation: uniform random over ~1,200 eligible days is mostly chop — which is CORRECT training — but any curation toward 'interesting' days (or player re-rolling boring days) teaches that trends are common and rewards overtrading. Separately, no-repeat sampling exhausts the pool after ~1,200 sessions and silent recycling would double-count learning.
MITIGATION: Lock uniform sampling in the spec; NO re-roll button; abandoned days count as played. Define pool-exhaustion behavior explicitly (new 'season' with disclosure). Publish the sampling rule in the app so the player knows boredom is the curriculum.

### [training/low/fix:v2] Forced 15:25 square-off means the player never practices the hardest short-option decisions — managing the 15:00-15:30 expiry gamma window and choosing his own flatten time — and learns that someone else always flattens him for free at a fair price.
MITIGATION: v1: square-off pays full modeled exit costs including stressed spread (not free). v2: optional 'manual close only' hard mode where the player must flatten himself by 15:29 or eat settlement.

### [leak/high/fix:v1] Client-side future leak: any architecture that ships the whole day's bars (or a parquet slice) to the browser leaks the future via devtools network tab, JS memory inspection, or cache — regardless of what the UI hides. This is the number-one implementation trap for replay games.
MITIGATION: Server-authoritative sim clock. The API physically returns only bars <= now; the browser never possesses future data. Acceptance test before v1 sign-off: open devtools, dump every response and window object, confirm nothing beyond sim-now and no real dates exist anywhere.

### [leak/high/fix:v1] Date leakage through side channels: bar timestamps in JSON payloads, expiry filenames (files are literally named by expiry date), the no-repeat ledger on disk, session state files, and pre-reveal log writes all carry the real date even if the chart hides it.
MITIGATION: Rebase every client-visible timestamp to a synthetic date preserving only time-of-day (no weekday shown — weekday + DTE leaks the Thu-vs-Tue expiry era); hash dates in the played-days ledger; buffer trade-log rows in memory and write real-dated records only after reveal; never expose source file paths in any response.

### [leak/high/fix:v1] Naive timeframe aggregation is a FUTURE leak, not a date leak: if the 15m/30m/1h view is served from pre-aggregated candles, the in-progress candle shows the completed bar — i.e., up to 59 minutes of the future. Subtler and worse than the date leak because it corrupts every decision.
MITIGATION: Aggregate strictly client-side from already-streamed 1-min bars; the last candle of every timeframe is always partial. Unit test: for every t and timeframe, candle(t) == aggregate(1-min bars <= t).

### [leak/med/fix:v1] Exact VIX + exact spot pair pins the exact date, not just the era. A lookup table (or a grep of the parquet sitting on the same disk) maps (spot open, VIX) to a unique day, upgrading the accepted era-leak to full event-day recall ('RBI announces at 10:00 today').
MITIGATION: Display VIX as a banded regime (e.g., <13 / 13-17 / 17-25 / >25) during play; exact VIX revealed in post-session review. Spot must stay real (locked requirement) — accept that residual, but do not hand over the second coordinate.

### [leak/med/fix:v1] The mandatory prev-day full chart can BE the tell: if yesterday was an iconic pattern (Jun 4 2024 election crash, Feb 24 2022, budget-day spike), today is fully known before the first bar prints. Prev-week H/L levels sharpen the same signature.
MITIGATION: Do not bias sampling broadly, but exclude a small explicit blacklist (~10-15 iconic dates) from the pool as 'known answers', and rely on the pre-reveal recognition prompt to quarantine any others. Document the blacklist so the sample bias is known and tiny.

### [leak/med/fix:v1] Refresh/resume hole: if a browser refresh or crash restarts the day at bar 1, the player replays the opening with foreknowledge; if it silently deals a new day, the half-seen day returns to the pool and can be re-dealt later — a delayed leak.
MITIGATION: Server-side session persistence: resume at the exact sim-clock bar. An abandoned session marks its day as played permanently. No path exists by which a partially-seen day is re-dealt fresh.

### [leak/med/fix:v1] Derived-analytics leak: IV, Greeks, or the payoff diagram computed using any post-now input — daily settle price, day close, end-of-day forward, or full-day realized vol — quietly imports the future into on-screen numbers.
MITIGATION: IV strictly from current-bar LTP; forward derived from ATM put-call parity at the current timestamp; explicit code review of every column feeding on-screen analytics for post-now provenance (this is a T1-T10 lookahead audit applied to a game — same taxonomy, LOOKAHEAD_CONTROLS.md).

### [leak/med/fix:accept] Pause-and-lookup: the player can pause at any decision point and grep the local parquet or Google the spot level. Unbeatable in a local single-player game — the boundary is honor, and pretending otherwise is self-deception.
MITIGATION: Accept as honor-system, but make it visible: state the honor rules in-app, log pause count and duration (especially pauses immediately before entries), and surface a 'pause profile' in the session report so contaminated sessions are at least self-flaggable.

### [leak/low/fix:v2] Raw OI magnitudes grew several-fold across 2021-2026 and famous expiry weeks have recognizable OI signatures — an incremental era/date fingerprint on the option chain view beyond the accepted spot-level leak.
MITIGATION: Show OI as within-day chain percentiles or normalized bars during play; raw OI in the post-reveal review.

### [realism/high/fix:v1] Flat 1-tick slippage materially understates exit costs exactly when they matter: stressed exits on short options, expiry-afternoon gamma hours, and OTM wings pay spreads that are multiples of 1 tick. The game will systematically overpay the player on his worst trades — the opposite of live.
MITIGATION: Same spread model as the fill engine: premium/moneyness/DTE-dependent base spread, widened on high-range and low-volume bars and after 15:00 on expiry day. Calibrate roughly against a few days of known live spreads (Principal's Angel terminal can spot-check current ones). Route the final cost table through COST_STANDARDS approval — it is still DRAFT and the hard rule applies even to a game that trains real behavior.

### [realism/high/fix:v1] Touch-equals-fill on stops and limits: filling a limit whenever bar low touches it overstates fills precisely when the queue is longest, and an SL-limit that gaps through must MISS — leaving the player naked short with the market running. The missed-stop experience is one of the most instructive events in live option selling and a naive engine never produces it.
MITIGATION: Trade-through fill rule for limits; gap-through SL-limit = unfilled order + open position + alert, forcing the player to handle it manually. Optional probabilistic partial fills in v2.

### [realism/med/fix:v1] Stale and freak prints: zero-volume minutes carry OHLC from a trade that may be many minutes old; the HF/bhavcopy lineage is documented to contain 0.00-price rows and spike ticks. The game would let the player trade with ghosts or get stopped out by a bad print.
MITIGATION: No fill on zero-volume bars; missing bar = no quote (never forward-fill into a tradeable price); sanitizer pass flags freak bars (spike vs neighbors) and excludes them from fills, stops, and marks. Run each candidate day through a data-quality gate (DATA_QUALITY_RULES) before it enters the sampling pool; drop irreparable days.

### [realism/med/fix:v1] Static margin at entry misses the defining short-vol experience: SPAN expands as spot trends against a short strangle, and live RMS force-liquidates you at the worst moment. A margin check only at order time teaches that margin is a one-time gate rather than a live constraint.
MITIGATION: Recompute approximate SPAN every bar; margin breach triggers a warning bar then forced liquidation at modeled stressed cost. Spread benefit exists only while both legs are held — closing the long leg instantly re-margins the short (and blocks the close if margin is insufficient), matching live RMS behavior.

### [realism/med/fix:v1] Expiry-day settlement done wrong teaches wrong pin behavior: real settlement is intrinsic vs the closing spot (last-30-min average), not the option's 15:29 LTP; deep ITM options go illiquid and near-money quotes decouple from theoretical value in the last hour. Settling at LTP misprices every expiry-day hold.
MITIGATION: Settle expiring ITM positions at intrinsic vs a last-30-min spot average computed from the 1-min spot data; OTM expires worthless regardless of residual 0.05 quotes; apply current STT treatment on exercised ITM; widen modeled spreads sharply after 15:00 on expiry day.

### [realism/med/fix:v1] Cost-model side-asymmetry: STT on options is sell-side on premium, exchange charges are on premium both sides, GST rides on brokerage+charges, stamp is buy-side — a 'flat per order' simplification distorts strategy comparison (short-premium styles pay measurably more). Small per trade, decisive over 500 logged trades.
MITIGATION: Implement the current-regime per-leg cost formulas in a config file (they are five lines of arithmetic, not a burden); show the full cost breakdown per trade in the review screen so the player internalizes cost drag. Get the table CEO+CIO-reviewed and Principal-approved per the COST_STANDARDS gate.

### [realism/low/fix:v1] Greeks from Black-Scholes with a guessed risk-free rate and spot (instead of the futures-implied forward) produce skewed put/call IVs and a misleading IV smile — the player is training his eye on artifacts.
MITIGATION: Derive the forward per timestamp from ATM put-call parity within the chain itself; label the IV method on the chain view. Cheap and correct — do it in v1.

### [realism/low/fix:accept] 1-min bars are the floor of achievable realism: sub-minute freak moves, momentary IV crushes, and the fact that a bar close is a single print mean intrabar reality is invisible. No fix exists at this data granularity.
MITIGATION: Accept explicitly and lean pessimistic wherever ambiguous: stops evaluated against bar extremes (adverse side), fills at the worse plausible price. Document the granularity limit in the app's methodology note so nobody later mistakes game P&L for tick-level truth.

### [analytics/high/fix:v1] Reset-deletes-history creates survivorship bias in the career record: blown-up bankrolls and rage-quit sessions vanish, and the surviving stats flatter the player — the exact failure mode the firm's own OOS-hygiene rules exist to prevent.
MITIGATION: Reset = new SEASON, never deletion. Trade log is append-only and immutable; bankroll resets open a new season while all-seasons and per-season views persist. No delete affordance exists in the UI at all.

### [analytics/high/fix:v1] Tiny-N point estimates will drive real conclusions: at 20-40 trades, a displayed '62% win rate' has a confidence interval spanning coin-flip to excellent, and the Principal will (humanly) act on the point estimate. The firm mandates DSR/CI discipline for its own strategies; the game must not hold the human to a lower standard.
MITIGATION: Wilson interval on win rate, bootstrap CI on expectancy, everywhere they appear; slices below a minimum N (e.g., 30 trades) render greyed-out with an 'insufficient N' badge instead of a number.

### [analytics/med/fix:v1] MAE/MFE computed from 1-min close marks understates true adverse/favorable excursion — on options even bar-to-bar moves are violent — so 'my stops are wider than my MAE' conclusions will be systematically wrong.
MITIGATION: Compute MAE from bar lows and MFE from bar highs of the position mark (bounding values), label them as bounds ('>=') not exact, and never present them as tick-accurate.

### [analytics/med/fix:v1] Regime-blind aggregation: pooling 2021 high-vol, 2023 dead-vol, and 2024 event-cluster sessions into one win rate makes every stat uninterpretable — a style that only works in one regime will look like a modest all-weather edge.
MITIGATION: Auto-tag every session at reveal with regime metadata (VIX band, trend/range/gap day classification, era, expiry-day flag); the dashboard defaults to regime-segmented views with the pooled number demoted to a footnote.

### [analytics/med/fix:v1] Hindsight-contaminated sessions (player recognized the day) inflate career stats and are indistinguishable from skill unless flagged at source.
MITIGATION: The pre-reveal recognition prompt writes a RECOGNIZED flag into the session record; analytics exclude flagged sessions by default with a toggle to include. Depends on the v1 prompt — flag and exclusion logic must ship together.

### [analytics/med/fix:v1] R-multiples are fabricated without stated risk: if the player enters with no stop, any R:R or expectancy-in-R number is derived from an invented denominator, and the dashboard will confidently report garbage.
MITIGATION: Order ticket requires an intended stop / max-loss field (auto-populated for defined-risk spreads); R computed only from stated risk; trades without it are tagged 'undefined-R' and excluded from all R-based stats rather than silently defaulted.

### [analytics/med/fix:v1] Post-exit 'what happened after' overlays teach should-have-held bias: every winner exited before the high looks like a mistake, but the overlay shows one path, not the distribution of outcomes at that decision. Systematic single-path counterfactual review trains exactly the wrong lesson (widen targets, drop stops).
MITIGATION: Frame post-exit paths explicitly as one draw ('counterfactual — single path'); make the aggregate MFE-capture-% stat (how much of available move was captured, across all trades) the headline exit-quality metric instead of per-trade hindsight; warn against rule changes off single instances.

### [analytics/low/fix:v1] Free-form journal tags drift ('fomo' / 'FOMO' / 'chased') and fragment the mistake/setup analytics into unusable slivers exactly when N finally gets large enough to matter.
MITIGATION: Controlled tag vocabulary via dropdown (setup / mistake / emotion lists, extendable deliberately) plus a free-text note field; a tag-merge utility for later cleanup.

### [analytics/low/fix:v2] Self-serve slicing is human PBO: the player slices the dashboard by tag x regime x timeframe until a flattering cut appears, then 'trades that setup' — multiple-comparisons bias with no trial counter.
MITIGATION: Enforce the min-N rule per slice (inherits the tiny-N mitigation) and display a standing caveat on filtered views ('exploratory cut — not evidence'). A formal trials counter is overkill for one human; the min-N gate does most of the work.

### [analytics/med/fix:v2] Improvement conflation: a rising equity curve over 100+ sessions may reflect growing familiarity with the 2021-2026 dataset's intraday personality (era-specific open-drive/reversal rhythms) rather than transferable skill — the game cannot distinguish learning the market from learning the tape.
MITIGATION: Rolling-window stats rather than cumulative-only; when BANKNIFTY mode lands, use it as an out-of-instrument check (does skill transfer to tape the player has never replayed?); ultimately the firm's paper-trading desk on LIVE current data is the true out-of-sample test — position the game as drill, not proof.
