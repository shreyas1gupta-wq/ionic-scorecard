## Purpose & context
Quantamental 0-100 scoring + Sell/Hold recommendation engine for stock holdings review. **NDPMS context: recommendation vocabulary is Sell or Hold ONLY, never Buy** — this reviews existing holdings, it does not solicit new positions. Two live use cases so far: (1) a 25-random-stock sample of the Nifty-750 universe (methodology validation), (2) a real 59-stock client portfolio pulled from NSDL CAS statements (priority production use).

## Dual-horizon scoring
Every stock gets TWO independent composite scores — 3-Year (fundamentals-tilted, 63/37 split before regime tilt) and 1-Year (technical-tilted, 40/60 split) — never blended into one number. DCF is excluded from the current build (see below); base weights renormalized across the other 7 pillars:

| Pillar | 3Y weight | 1Y weight |
|---|---|---|
| Quality | 20% | 16% |
| Growth | 20% | 16% |
| Value | 18% | 16% |
| Stage/Technical | 14% | 26% |
| Sector & Macro | 11% | 13% |
| Ownership Flow | 9% | 8% |
| Accumulation | 8% | 5% |

## Pillar formulas (all percentile-ranked, ALL inputs winsorized 2%/98% before ranking — added v4 to stop a single outlier claiming an extreme rank)
- **Quality** = mean(pctile(ROE, sector-neutral), pctile(ROCE, sector-neutral)). ROE = Net Profit/(Equity Capital+Reserves); ROCE = Operating Profit/(Equity+Borrowings). Cyclicality-aware lookback intended (7-10yr Cyclical / 3-5yr other) — **not independently re-verified in the shard computation, flag for audit**.
- **Growth**: 3Y uses 3yr revenue CAGR; 1Y uses 1yr/TTM revenue growth — universe-wide percentile, not sector-neutral.
- **Value** = 0.25×pctile(−PE, whole universe) + 0.35×pctile(−PE, sector×market-cap-tier) + 0.20×pctile(−PB, sector×tier) + 0.20×pctile(FCF Yield, sector×tier). Sector×tier grouping cascades to sector-only, then universe, if a bucket has <5 members (**this fallback fires constantly on small reference samples — matters less at full 750-universe scale**). Fixed 2026-07-17 after catching that sector-only grouping is misleading when a sector's member mix skews to a different size tier than the stock being scored.
- **Stage/Technical**: mechanical baseline = mean(pctile(return, universe), pctile(return, sector)) over 12M+24M[3Y]/3M+6M[1Y], gated by price vs 200DMA[3Y]/50DMA[1Y], **±5pt RSI nudge on the 1Y score only**. **For any stock that has gone through the technical-agent pass, this mechanical 3Y score is REPLACED by the agent's own "Chart Long-Term Technical Pattern Score"** (see Technical agent section) — real monthly-chart judgment, not just DMA math, with an explicit choppiness penalty. 1Y stays mechanical (near-term momentum, a distinct read from the long-term pattern).
- **Sector & Macro** = pctile(sector-mean return, universe) + regime-cyclicality fit adjustment (see Regime below).
- **Ownership Flow** = pctile(mean FIIs_qoq+DIIs_qoq), trailing 6-of-8 quarters[3Y] / 1-2 quarters[1Y].
- **Accumulation** = pctile(OBV slope), 6-12mo[3Y] / 1-3mo[1Y].
- **Intrinsic Value (DCF)** — **EXCLUDED from the build so far.** Original spec had it at 12%/5% weight; the mechanical two-stage terminal-value formula produced implausible 85-121% implied-growth figures (thin 13.5%-6% discount-terminal spread massively amplifies terminal value) even after a single-stage-perpetuity fix brought it to more sane 8-13% figures. **Retired as a formula entirely — now the fundamental analyst's own reverse-DCF judgment call** (a field in their research output), not a script. Needs reinstating as a real pillar weight once the analyst-judgment version has a track record.

## Regime (6 fixed categories, drives both a weight tilt and Sector&Macro's fit adjustment)
1. Global Risk-On/Easy Liquidity, 2. Global Risk-Off/Tightening, 3. India Domestic Expansion, 4. India Domestic Slowdown/Stress, 5. Value/Cyclical Rotation, 6. Growth/Quality Leadership.
**Current call (Cyrus Daruwalla, verified 2026-07-17, web + local data):** Primary = Value/Cyclical Rotation (mild — ~1/4-1/5 the magnitude of the 2022-23 melt-up), Secondary = India Domestic Slowdown/Stress (mild). Blended 70/30. **Regime fit adjustment currently applied: Cyclical +4.6, NotCyclical −2.6** to the Sector&Macro pillar score. **Weight tilt table** (hand-set, NOT rigid — a starting point the qualitative analyst can override per-stock, mild magnitude by design):

| Tag | Tilt |
|---|---|
| Cyclical | Value +3, Sector&Macro +3, Growth −2, Quality −2, Stage −2 |
| NotCyclical | Quality +3, Growth +2, Stage −3, Sector&Macro −2 |

Regime should be re-checked periodically (monthly-ish), not every run — it's meant to be slow-moving.

## Overlay gates (multiplicative, applied after the weighted composite)
- **Balance-Sheet Safety**: RED if D/E>2.5 or Interest Coverage<1.5 → caps score at 40. AMBER if D/E>1.5 or IntCov<3 → ×0.85. **Financial Services / Banking / NBFC / Insurance sectors are EXEMPT from the D/E trigger** (leverage is the business model, not distress — caught on LICHSGFIN, then confirmed systemic across BAJFINANCE/SBIN/HDFCBANK/BAJAJHFL/HDBFS on the real portfolio, ~17% of that book's value). These sectors get `bs_flag = "N/A-financial-sector"` (no gate applied, not silently GREEN) — genuinely needs a sector-specific CRAR/asset-quality assessment instead, deferred to the qualitative layer.
- **Liquidity**: RED if median 60d turnover < size-tier bar (₹5cr/1cr/25L for Large/Mid/Small market-cap tercile) → caps at 40.

## Penalty / Boost (±10, exponential penalty)
`penalty = -min(10, 2^(redflag_count) - 1)` — 1 flag=-1, 2=-3, 3=-7, 4+=-10 capped. Red flags counted: Interest Coverage<1.5 (all sectors), D/E>2.5 (**non-financial sectors only** — same exemption as the gate, fixed 2026-07-18 after finding this double-penalized financials a second way even after the gate itself was fixed), negative 1yr revenue growth, >15pp deceleration (3yr CAGR vs 1yr growth), **and analyst-estimated `expected_next_3y_growth_pct` < 10%** (added v4 — this is a forward analyst estimate, not historical CAGR).
`boost = +3` (partial, quant-only) if zero red flags AND Quality+Value both >60th percentile. **Full +10 boost reserved for a qualitative-confirmed clean bill of health** (no red flags + positive analyst sentiment + confirmed balance-sheet health) — not yet wired as an automatic rule, currently manual/analyst-driven.

## Research pipeline (Sonnet-only as of 2026-07-18 — Opus dropped for cost)
**One Sonnet agent per stock** (not two separate stages) doing: (1) ~3min-equivalent deep research — business model, earnings-quality check (flag one-off items distorting reported growth/margins), sector-cycle context, own reverse-DCF-style valuation judgment, a genuine forward-looking `expected_next_3y_growth_pct`; (2) the agent's own ~1min self-review before finalizing. Persona routing by sector (industrials/financials/consumer/IT/pharma personas — see the roster in root CLAUDE.md).
**Escalation criteria — narrow, deliberately:** reserve `escalation_flag:true` ONLY for genuine analytical disagreement (a real Hold-vs-Sell judgment call, a methodology gap that likely affects other stocks too). **Price/fundamentals data has a scrape-date lag vs. today's real market — stale-price findings are EXPECTED and NEVER escalation-worthy on their own** (this was a real mistake in the first pass — USUAMART's stale P/E got escalated when it should have just been silently corrected; at 750-stock scale this pattern would escalate constantly and defeat the purpose). Escalations get logged for Principal adjudication, not resolved by the agent.
Fundamental-only language in all commentary fields — no technical/chart discussion (that's the separate Stage/Technical agent's job, in its own field).

## Technical agent (separate from the fundamental analyst)
One technical-persona agent per stock, reads the real price parquet, resamples to monthly, forms genuine judgment on multi-year swing-high/low structure, MA-stack ordering, volume character (checks specifically for climax/distribution signatures). Produces `chart_long_term_technical_pattern_score` (0-100, replaces the old mechanical "O'Neil Stage" label) + `choppiness_flag`/`choppiness_penalty_applied` (0 to -15, folded into the score) + `technical_commentary` (chart language IS allowed here, unlike the fundamental fields).

## Recommendation logic
Per horizon, independently: gate RED → Sell. Score missing → **No Recommendation** (never force a call on a data gap). Else: **score ≥40 → Hold, <40 → Sell** (default threshold). **STCG-tax-aware threshold (30 instead of 40) designed but NOT YET ACTIVE** — applies only if a position has real transaction/holding data showing it's profitable AND still short-term-capital-gains-exposed (avoids recommending an exit that needlessly triggers the higher STCG tax rate vs. waiting for LTCG treatment); needs client holding-date data to activate.
**Overall = Sell if EITHER horizon says Sell** (conservative — surface any real concern, don't average it away). **The qualitative analyst's `your_recommendation` OVERRIDES the quant-only call entirely** where research exists (full discretion, e.g. LICHSGFIN quant-Sell → analyst-Hold on sector-aware leverage reasoning).

## CLIENT PORTFOLIO LAYER (v6, FROZEN 2026-07-18 — Principal rulings of this date)
This layer converts stock scores into actual NDPMS client-portfolio feedback. Client identity on all client-facing deliverables: **Ionic Wealth**.

### Ionic Score (the ONE number a client sees)
`base = 0.60 × final_3y_adj + 0.40 × final_1y_adj` (Principal ruling: 60/40 blend, never show the two legs to clients).
Then a bounded **Forward Adjustment** (Principal ruling: "give a little more weightage to growth — expected next 3-5y types," making the score forward-looking, in clients' best interest):
- **Growth leg** from the analyst's forward growth estimate (`expected_next_3y_growth_pct`, horizon = FUTURE 3-5yr CAGR view, explicitly NOT past growth — Principal order): **v6.2 table (2026-07-18, Principal: "add more"):** <5% → **−15** | 5-10% → **−5** | 10-15% → 0 | 15-20% → **+5** | 20-25% → **+10** | ≥25% → **+15** | **+20 EXCEPTIONAL tier**: ≥25% forward growth AND high ROE (≥20%) AND little-to-no share dilution (share-count CAGR <2%; the mechanical layer marks candidates on growth+ROE, the analyst/FM confirms the dilution test until a share-count field lands in the quant CSV). (Principal's message gave overlapping bands "20-30 → 10, >25 → 15"; frozen as 20-25 → +10, ≥25 → +15 — amend if a different split was intended. v6-original table was −6…+6.)
- **Conviction leg** from analyst-vs-quant: analyst says Sell → −6 | analyst Hold where quant overall said Sell (a "rescue") → +6 | agreement → 0.
- Total adjustment clamped to **±20** (widened from ±10 in v6.2 so the −15/+20 growth bands bite). **Two coherence caps:** (a) **Low-growth cap (v6.1): expected growth <10% → net forward adjustment ≤0** — a sub-10%-growth name can be penalized, never boosted (without this, the conviction rescue could perversely LIFT a low-growth name's score after the v4 red flag flips its quant rec — observed on TCS/INFY/NATIONALUM/TATASTEEL, corrected same day); (b) **Analyst-Sell cap (v6.2): analyst recommendation Sell → net forward adjustment ≤0** — a name we are telling the client to exit is never score-boosted by the adjustment (guards against high-growth-off-tiny-base names like JIOFIN reading as improving while rated Sell). `ionic_score = clamp(base + adj, 0, 100)`, 1dp. Mechanical-layer implementation: `09_PRODUCT/scripts/compute_client_scores.py` (frozen, rerunnable).
- **v4 growth red flag is LIVE in the quant layer as of 2026-07-18** (same Principal order): the analyst-estimated growth <10% red flag is now COMPUTED into redflag_count/penalty/final_*_adj (it was vintage-stale before — the quant CSV predated the analyst estimates). So sub-10% growth is penalized twice by design: once in the quant penalty counter (exponential, hits both horizons' final scores) and once via the forward-adjustment cap (client score can't be rescued upward). Pre-recompute snapshot preserved at `results/portfolio_quant_pre_v4flag.csv`.
Design note: the conviction leg keeps the displayed score coherent with the analyst-governed call (e.g. LT: quant base 39.5 would read as a score-Sell; +4.0 net forward adj lifts it to the Hold band its analyst rescue implies). Where score and call still diverge (e.g. a >50 score with an analyst Sell), the client sheet carries an auto-generated **Score-vs-Call note** — show honestly, explain in Rationale; never force the score to match the call.

### Recommendation logic — client portfolios (two-gate; supersedes the plain ≥40/<40 rule WHEN portfolio weights are known)
Client vocabulary: **Sell / Trim / Hold** (Trim = the frozen term, Principal ruling; phrased as "Trim to ~X% of portfolio" — target weight, client-actionable).
- **Gate A (stock quality):** analyst override governs direction. Analyst Sell → Sell. Else ionic_score <40 → Sell.
- **Gate B (concentration, Trim band):** ionic_score 40-50 AND position >2.5% of book → Trim (this is the Principal's "raise the bar to 50 for big positions," implemented as Trim-not-Sell). Overweight sector with weak forward view (Sector&Macro + regime) tightens the same band.
- **Concentration guidance (NO hard caps — Principal ruling 2026-07-18):** single stock 5-10% = okay, but if forward growth is modest, advise some reduction; **>10% = "a little bad"** → Trim advice expected unless FM affirms conviction; **>20% = extreme** → strong Trim advice. The FM + company future expectations + score decide the target weight case-by-case — buying price, investor IPS, and large-vs-small-cap context all matter and none is a hard rule. Micro/small-cap positions get a lower comfort band than large-caps at the same %.
- **Trim targets are set by the agentic FM pass (judgment), not a formula.** The mechanical layer only FLAGS candidates; the FM sets "Trim to ~X%" and the one-line client reason.
- STCG-tax-aware threshold (30) remains designed-but-inactive until client holding dates/costs arrive (adopted default); client sheet carries a "confirm tax status before executing" line.

### Frozen run-protocol (workflow / agents — how a scoring run executes)
1. Data: per SCRAPING_SOP.md (post-results-season refresh + D-009 gate) → quant CSV via the scoring engine above.
2. Research: **one Sonnet agent per stock**, persona-routed by sector (industrials=Rohan / financials=Meera / consumer=Priya / IT+telecom=Karan / pharma+chemicals=Sneha), single pass = deep research + earnings-quality one-off check + reverse-DCF judgment + forward 3-5y growth estimate + self-review; output = `pf_qual_<SYMBOL>.json` (exact schema per this file), saved immediately per stock (never batched saves).
3. Parallelism: 10 agents per batch max (Principal authorization 2026-07-18 for this workstream; firm default D-023 = 3 elsewhere). Every batch: schema-validate all JSONs, checkpoint to the PROGRESS file, then launch the next.
4. Escalations: narrow criteria (see Research pipeline section); logged for Principal adjudication, never resolved by the desk.
5. FM pass (client books only): agentic fund-manager review sets Trim targets + Sheet-2 narrative (skill: `agentic-fund-manager`).
6. Ship gate: **no client deliverable ships without Principal sign-off** (adopted default 2026-07-18). Cadence: quarterly full re-score post results season + event-driven re-checks.
7. Analyst kit: the portable analyst skill + analyst Excel (see ANALYST_KIT/) is how an external analyst runs step 2 on their own Claude — write-back in our exact JSON schema, Sonnet tier (adopted default). **750-universe research: METHOD FROZEN 2026-07-18; the actual 750-stock run starts only on explicit Principal go.**
