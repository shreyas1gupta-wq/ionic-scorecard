## PART B: AGENT SELF-IMPROVEMENT METHODS (ranked)
Scope constraint: we are markdown personas + skills only — NO vector DB, NO fine-tuning, NO live RL loop. Verdicts respect that. Ranked adopt-first.

| Rank | Method | Mechanism | Maps To Our Setup | Verdict |
|------|--------|-----------|-------------------|---------|
| 1 | **Reflexion** (Shinn et al., NeurIPS'23; 2024-26 ext: SCoRe, ReflexiCoder) | After a failed attempt, the LM writes a natural-language self-critique and stores it in an episodic memory buffer that is prepended on the next attempt — learning via text in context, no weight updates. Known failure mode: reflection assumes a *causally correct* diagnosis, which breaks under binary pass/fail feedback. | This IS our `/retro` → `## Lessons Learned`. Upgrade: add a STRUCTURED failure taxonomy (root-cause tag per lesson: data-artifact / cost-model / overfit-DSR / cadence-miss / sycophancy) so lessons cluster and dedupe instead of prose sprawl; require the lesson to name the causal diagnosis, not just the symptom. | **ADOPT** (enhancement — zero new infra, just a taxonomy field in the retro skill) |
| 2 | **LLM-as-Judge rubrics** (2024-26: LongJudgeBench, BabelJudge, Judge Reliability Harness) | An LM scores outputs against an explicit rubric. Robust finding: judges carry position bias, verbosity bias, and self-enhancement bias (a model rates its own output higher); a fixed reference answer beats prompt-only scoring, and off-the-shelf judges need domain calibration. | Upgrades `/review-team` + coaching scoring: publish an explicit written rubric (honesty / decision-usefulness / token-efficiency already exist — add anchored 1-5 descriptors), and codify the anti-self-enhancement rule = an agent NEVER judges its own memo (already partly true via independent Quant re-derivation and Red Team). | **ADOPT** (rubric is text; directly hardens existing quarterly scoring) |
| 3 | **Voyager skill library** (Wang et al., 2023; 2025-26 lifelong-learning confirmations) | An ever-growing library of executable code skills, each indexed by an embedding of its description; new tasks retrieve top-k relevant skills and compose complex behaviours from simpler stored programs — compounding capability without fine-tuning, alleviating catastrophic forgetting. | We already have `.claude/skills/` — this is the structural twin. Gap = discipline: maintain a SKILL_INDEX.md (one-line description + when-to-use + composes-from) so agents retrieve/compose existing skills instead of re-deriving; promote a repeated ad-hoc procedure into a named skill (Voyager's "add to library" step). | **ADOPT** (text index + skill-authoring convention; no embeddings needed, description-match by hand/grep) |
| 4 | **Constitutional AI self-critique** (Bai et al., 2022; 2024-26: C3AI, Deliberative Alignment, SPRI) | Model critiques and revises its own output against a written constitution of natural-language principles, then (in the full method) trains on that via RLAIF. The *critique-and-revise* front half needs no training — it is pure prompted self-correction against explicit principles. | Our "firm protocol" (never guess / PIT / approved costs / DSR+PBO / tag INFERENCE) IS a constitution. Adopt the critique half only: a pre-submission checklist pass where the agent revises its memo against the numbered protocol before filing. Skip RLAIF. Complements Red Team (external critique) with cheap internal critique. | **ADOPT-LITE** (critique/revise pass only; the RL half needs infra we lack — take the front half) |
| 5 | **Self-Refine** (Madaan et al., 2023; 2024-25 test-time-scaling line) | Same LM plays Generator → Critic → Refiner in a loop: draft, self-feedback, improve, repeat — no extra training. Gains come because spotting-and-fixing is easier than one-shot perfection. Risk: without an external signal it can rationalize/agree with itself. | A one-pass "refine before submit" on hypothesis one-pagers and IC memos (draft → self-feedback against kill-criteria completeness → tighten). Bounded to 1 iteration to avoid token bloat and self-agreement drift. | **ADOPT-LITE** (cap at 1 pass; overlaps heavily with #4 — pair them, don't double-spend tokens) |
| 6 | **Memory decay / pruning** (from MemoryBank Ebbinghaus curve, A-Mem, MemoryOS tiers — the NON-vector idea only) | MemoryBank ages memory strength on an Ebbinghaus forgetting curve; tiered systems (MemoryOS) split short/medium/long-term with different retention rules; A-Mem links related notes into an evolving network. | Transplant the *pruning* idea, not the storage tech: `## Lessons Learned` grows unbounded and dilutes the persona prompt. Add a quarterly prune — archive stale/superseded lessons to a cold KNOWLEDGE_BASE appendix, keep only live ones in the persona (hot tier). Prevents context bloat at spawn time. | **ADOPT-LITE** (adopt pruning discipline; SKIP the vector/embedding storage — no DB) |
| 7 | **DSPy / MIPROv2 prompt compilation** (Khattab et al.; MIPROv2 2024-25) | An optimizer takes a typed program + a dataset + a metric function, then uses Bayesian optimization to propose instructions and few-shot demos, evaluates on mini-batches, and keeps only what moves the metric — automating prompt tuning instead of hand-editing. | Conceptually maps to compiling our skill-prompts against the AP/10k-token efficacy metric — but requires an automated eval harness + labelled trial set + a programmatic compile loop that reruns and scores variants. | **SKIP** (needs an offline eval harness + programmatic optimizer loop we don't have; revisit only if we build a scored prompt-regression bench) |
