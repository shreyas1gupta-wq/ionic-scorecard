[OPINION, but grounded in what DSR mechanically deflates] The DSR trial count attaches to the **signal search**, not to the instrument. DSR (Bailey–López de Prado) deflates an observed Sharpe against the *expected maximum* Sharpe achievable under N configurations tried in pursuit of a positive result on the same underlying phenomenon. The phenomenon here is the FF term-structure edge — one discovered signal. The calendar and the vertical are two instrumentations of that one signal, not two independent discoveries. So the ~34 family trials from K-012 **carry forward in full**; this build adds to them, it does not reset them. CIO ruling §b already ordered exactly this, and it is correct.

Why this must be non-negotiable: the "new vehicle = fresh N=1" move is the precise selection bias DSR exists to catch. If a vehicle swap reset the counter, you could manufacture any DSR you like — try the signal on ten structures, reset each time, report only the winner's Sharpe against N=1. That is the deflation-defeating trick in a costume. The honest denominator for the eventual Gate-4 DSR is **34 (K-012) + every strategy configuration this vertical build actually touches** — each strike-selection rule variant, each distance cap, each D+1-vs-same-day timing rung, each gate-vs-drop toggle is a trial and goes in the ledger the moment it is run, not retroactively.

Two refinements so we are precise, not just conservative:
- **DSR wants *effective independent* trials, not raw count.** The 34+new are heavily correlated (same signal, overlapping name-days, adjacent strikes). Correlation lowers effective N, which is *less* punitive — but you may only reduce N by **measuring** the trial correlation (cluster the config return-streams; effective N = number of clusters). Default to the raw honest count; earn any reduction with a number, never by assertion.
- **PBO is the one thing that is genuinely vehicle-local.** CSCV runs on *this* backtest's config matrix, so PBO is computed on the vertical's own grid. But the same honesty applies: PBO must ingest **every configuration actually explored in this build**, not the tidy 3×3 you choose to present. A clean PBO on a cherry-picked sub-grid is theatre.

So: DSR trial count = inherited + additive (deferred until a positive raw forward edge exists, per CIO §b — I endorse that ordering; deflating a ≤0 edge is wasted tokens). PBO = computed fresh on this vehicle, but over the *complete* config set. The signal-existence placebo battery Nikhil ran (100th-pct vs turnover/premium nulls) does **not** add to the strategy-Sharpe trial count — different null, different test — and equally it cannot be spent as evidence of *profitability*. It proves information is present; it says nothing about whether the vertical monetizes it.

[INFERENCE — this is the hazard I would design the whole build around] The pre-registered spec DROPS any name-day where no OTM hedge strike clears the liquidity floor within the distance cap (§6, kill #1/#3). Framed as fill realism that is correct and necessary. But framed statistically it is **endogenous sampling**: hedge-leg illiquidity is very plausibly *correlated with the FF signal's own payoff*. - **Denominator discipline (KB lesson 8, and my own FF lesson).** Do NOT normalize return by net credit.
