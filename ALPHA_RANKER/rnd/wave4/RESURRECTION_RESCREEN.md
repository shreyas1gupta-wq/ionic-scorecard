## 2. Method (scripts-first, all thresholds pre-registered before computing)

Pipeline (paths, all under `rnd/wave4/`, reusable): loads every `rnd/cards/*.json`, merges each row
with the firm's own **existing money-first rescore** (`rnd/scoreboard_v2.csv`, generated by
`rnd/pragmatic_score_v2.py` — a script this same persona wrote in a prior session, whose docstring
already documents "PBO/CSCV structurally saturated... ADVISORY only, never a hard kill" per
`CONSOLIDATION.md` HARNESS FIXES #1). Where a card predates the last v2 run (39 of 273, mostly very
recent composite cards), a fallback pipeline recomputes the same logic directly from the raw card.

**Pre-registered structural-kill rules (any one disqualifies a card from rescue, permanently):**
1. **lag-fail**: `lag_test_delta > 0.25` (or an explicit `pass:false`/`gates.lag_ok:false`).
2. **placebo-fail**: `|placebo_ic| > 0.02` (or explicit `pass:false`).
3. **era/panel sign-flip**: pre-2015 vs post-2015 `ic_mean` (or a 5Y vs 21-yr-panel companion card) disagree in sign.
4. **monotonicity broken**: decile monotonicity `< 0.15` (near-zero or inverted ordering — distinct from merely "weak," which is a caveat, not a kill).
5. **documented cost-shortfall**: real positive gross return (`>2%/yr`) that costs eat to `<=0` net — a genuine economics problem, not a power problem.
6. **wrong economic sign**: where the expected direction is *confirmed* (backlog registry `sign` field, or an unambiguous keyword match — asset-growth, accruals, size, BAB, low-vol), a **negative** signed-IC means the empirical relationship runs opposite to the hypothesis. Different from "IC_IR below the 0.20 house threshold" — this is a real directional miss, not underpower.
7. **documented no-signal conclusion** in the card's own text ("genuinely no signal," "not distinguishable from a shuffle-null," "coinflip").
8. **manual overrides** — named artifacts documented in the firm's own prior research memos that an automated field-check cannot see (evidence lives in prose, not every card's json): see §3.

**Never used to kill (per the Principal's directive, shown for context only):** `newey_west_t`, `dsr.dsr`, `pbo.pbo`, raw `IC_IR<0.20` in isolation, small `n_dates` in isolation.

**Rescue score (money-first, power-agnostic)** = mean of whichever of these are available per card:
`min(1, |ic_mean|/0.05)`, `min(1, |net_LS_v2|/0.30)`, `min(1, |spread|/0.10)`, decile monotonicity
(0–1), and sign-stability across the card's own `regime_breakdown` (bull/bear/sideways ×
high/low/normal-vol — fraction of buckets sharing the majority sign). PBO/DSR/t are **not** inputs.

**Recommendation logic:**
- **GENUINELY-DEAD-DESPITE-RESCREEN**: primary effect (`ic_mean`/`spread`) below a trivial floor (0.01 / 0.02), OR sign flips across regime buckets (majority-sign fraction < 0.5).
- **NEEDS-MORE-DATA**: fewer than 2 independent metrics available, or `n_dates < 30`.
- **FORWARD-TEST-CANDIDATE**: rescue score ≥ 0.30, clean on all of the above.

**Tier split within FORWARD-TEST-CANDIDATE (this rescreen's own contribution beyond a blanket "PBO is advisory" pass):**
- **Tier A** — a single, pre-registered hypothesis (`backlog.json`/`backlog_scout.json` match) with a modest search space (`n_trials < 100`). High PBO here is consistent with CSCV small-sample degeneracy, exactly the Principal's "power problem" framing.
- **Tier B** — composite/ensemble constructions searched over many leg combinations (`n_trials` often 300-480) and/or with no backlog pre-registration found. A high PBO on these may be PBO **correctly** catching combinatorial overfitting from the search itself, not merely reflecting low power. Shown, ranked, but flagged lower-confidence — the Principal should weight these more skeptically than Tier A.

## 6. Metric-reliability caveat (read before quoting any number above)

`CONSOLIDATION.md` documents a real harness bug: 1Y/5Y long-short returns were annualized by a
uniform ×12 regardless of horizon, inflating true magnitudes ~12x (1Y) to ~60x (5Y) — e.g. one raw
card showed a "367%/yr" edge that is actually ~30%/yr. `rnd/scoreboard_v2.csv` (`pragmatic_score_v2.py`,
already fixed by this persona in a prior session) carries the corrected `net_LS_v2`/`gross_LS_v2`
fields, used everywhere above where available. **39 of the 273 low-power cards are newer than the
last `scoreboard_v2.csv` run and have no corrected figure** — for these, `net_ls` is shown as "not in
v2" and was **excluded from the rescue score** (only `ic_mean`/`mono`/sign-stability were used) rather
than risk using the unreliable raw number. Re-running `pragmatic_score_v2.py` against the current
`cards/` snapshot would close this gap.
